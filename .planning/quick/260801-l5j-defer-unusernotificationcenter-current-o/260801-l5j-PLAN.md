<objective>
Stop `RootShellView`'s cold-launch path from synchronously calling `UNUserNotificationCenter.current()`.
`ViewLoadLogger` measured Dashboard's first `.onAppear` at ~3063ms on a real device; the root cause
(documented in the source todo, corroborated by Apple Developer Forums thread 53390) is that
`ReminderService()`/`WeeklySummaryService()` are eager `private let` stored properties on
`RootShellView`, and their default init argument evaluates `UNUserNotificationCenter.current()` —
a known main-thread-blocking first call (XPC connection setup to `usernotificationsd`) — the instant
`RootShellView` is constructed, before Dashboard's first frame can appear.

Source: `.planning/todos/pending/2026-08-01-defer-unusernotificationcenter-current-out-of-rootshellview-cold-launch.md`.

Fix approach (the todo's first sketched option): make the notification-centre resolution **lazy**
inside `ReminderService`/`WeeklySummaryService` themselves — the `center:` init parameter becomes
`@autoclosure @escaping`, and the class stores a `private lazy var center` computed from it on first
actual read. Since `center` is only ever read inside `requestAuthorization()`, `schedule()`, `cancel()`,
and `scheduleIfEnabled()` — all only called from `RootShellView`'s async `Task { await ... }` blocks —
`UNUserNotificationCenter.current()` is deferred off the synchronous construction path entirely, with
zero changes required to `RootShellView.swift` itself and zero changes to the existing DI/testability
pattern (tests keep injecting `FakeNotificationCenter()` exactly as they do today).

This same fix, applied at the Services layer rather than at any one call site, also transparently
resolves the identical latent issue at `ReminderSection.swift`, `WeeklySummarySection.swift`, and
`HealthStep.swift` (all three construct `ReminderService()`/`WeeklySummaryService()` eagerly too) —
without touching any of those three files.

Purpose: Dashboard's cold-launch first-appear time should drop from ~3000ms to roughly the
container-load figure (~10-50ms) plus normal SwiftUI mount time, per the source todo's stated goal.
Output: `ReminderService.swift`/`WeeklySummaryService.swift` with lazy `center` resolution, two new
unit tests proving the laziness contract, a full-suite verification pass, and a DEVLOG entry.
</objective>
