<objective>
Add a dev-diagnostics view-load-time logger so that, when running the app from Xcode (physical
device or simulator), we can see how long each top-level view (Dashboard, Insights, History,
Settings) takes to become visible - both on cold launch and on every subsequent tab switch. Today
there is zero timing visibility into view loads; regressions can only be eyeballed.

Source: `.planning/todos/pending/2026-07-31-add-view-load-time-logger-for-cold-start-and-tab-switches.md`.

The design uses one shared "mark navigation requested -> log on appear" primitive for both cases,
per the todo's own hint that a tab switch is just `.onAppear` firing again on an already-live view:
- **Cold start**: the reference point is set the instant `drinkpulseApp`'s `containerState` becomes
  `.ready(...)` (STARTUP-02's existing container-load path, `ContainerLoadState.swift`) - the
  earliest safe point, before `RootShellView` (and therefore `DashboardView`, the initially-selected
  tab) is even constructed. This ordering guarantee matters: SwiftUI does not guarantee parent
  `.onAppear` fires before a child's, so marking inside `RootShellView.onAppear` itself would risk a
  race where Dashboard's `.onAppear` fires first and finds no pending mark.
- **Tab switch**: the reference point is set in `RootShellView`'s `.onChange(of: selectedTab)`,
  which necessarily runs before the newly-selected `Tab`'s content view appears.
- Both paths funnel into the *same* `ViewLoadLogger.logAppear(_:)` call added to each top-level
  view's `.onAppear`, which logs the elapsed time since the last mark via `os.Logger`
  (subsystem `com.drinkpulse.app`, category `performance`) and also brackets the same interval with
  an `OSSignposter` interval so it shows up in Instruments' Points of Interest track on a
  physical-device trace, not just as Console text.

This is dev-diagnostics only, not shipping UX: the entire logger, its mutable timing state, and the
signposter are gated `#if DEBUG` in one file, so it compiles to nothing in Release. No SwiftData
model changes, no new stored properties, no user-visible UI - excluded from the UI-test requirement.
</objective>

        `milliseconds(pending.start.duration(to: ContinuousClock().now))`; log
        `logger.notice("View '\(viewName, privacy: .public)' appeared in \(elapsedMs, privacy: .public) ms")`;
        clear `pending` to `nil` (one mark is consumed by exactly one appear).
      - `static func milliseconds(_ duration: Duration) -> Int64` (internal, not private, so the
        test target can call it via `@testable import`): same whole-millisecond truncation as the
