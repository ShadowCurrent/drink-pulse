<objective>
Finish the History list: stop recomputing sections on every body pass, remove the last duplicated
row chrome, and close the blank-screen gap that shrinking the fetch window opened.

- **B8-1** (`worth-fixing`): `daySections` is still called inline in `ForEach`, so a
  `Dictionary(grouping:)` plus a sort plus N calendar computations run on every body evaluation —
  not only when `events` changes, but whenever anything else invalidates the view. Cache it.
- **A4-2** (`worth-fixing`): the section titles are now precomputed, which introduces a correctness
  obligation the per-render version did not have — a precomputed "Today" goes stale if the app stays
  foregrounded across midnight. That refresh is part of this fix, not a follow-up.
- **B10-1** (`worth-fixing`): there is no state for "the current window is empty but older data
  exists", so the user sees a completely blank `List`. This became materially more likely when quick
  task `260802-uia` shrank `listPageDays` from 90 to 7 — a user who last logged a drink 10 days ago
  now opens History to a blank screen.
- **B9-1** (`worth-fixing`): the same three-line row-chrome triple is repeated on all three row
  kinds; B10-1 would make it a fourth copy.
- **A2-1 / A3-2** (`nit`): a conditional chain with no terminal branch, and an unbounded singleton
  query that should state its bound like the query two lines below it.

Purpose: the last plan in the phase, and the one that makes the earlier pure functions actually pay
off at render time.
Output: a cached section list with a correct refresh contract, a shared chrome modifier, a labelled
loading state, and a new UI-test fixture.
</objective>

| launch arguments → app state | A new UI-test seeding fixture crosses from the test process into app startup and inserts records. |
| cached view state → rendered dates | Precomputed section titles are time-dependent data; a stale cache misreports which day a drink belongs to. |
| `@Query` fetch bounds → memory/CPU | Query bounds determine how much of the user's history is materialised at once. |
