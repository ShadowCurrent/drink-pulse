<objective>
Collapse the duplicated guideline-choice row into one component, fixing the accessibility defect
that the duplication produced.

- **A7-2** (`worth-fixing`): the guideline-choice row is inlined in both `GuidelinePickerSheet` and
  `GuidelineStep`, and the two copies have diverged three ways — different name source, different
  checkmark symbol, and a selected-state accessibility trait present in one and absent in the other.
- **C14-4** (`worth-fixing`): in `GuidelinePickerSheet`, selection is conveyed *only* by a checkmark
  glyph. There is no `.accessibilityAddTraits(.isSelected)` and the image is neither labelled nor
  hidden, so a VoiceOver user hears the guideline name and threshold summary with no selected state.
  The sibling screen already does this correctly — this is the exact failure mode A7-2's duplication
  predicts.
- **A1-2** (`nit`): the picker filters the enum in `body`, allocating a fresh array on every body
  pass, while the onboarding step hard-codes the same six cases. Identical today; silently divergent
  the day a seventh guideline is added.
- **B9-2** (`nit`): one screen states its list style explicitly, the other inherits the platform
  default. Same rendered result, two conventions.

Purpose: one row component and one source of the choice list, so the next guideline added cannot
reintroduce any of these four findings.
Output: a shared static list, a shared row view, and a UI test pinning the selected-state trait.

Runs in parallel with 07-03 (wave 2) — zero file overlap. Depends on 07-01 only for decisions
**D-03** (canonical checkmark symbol) and **D-05** (whether B9-3's visual conversion is in scope).
</objective>

tests can address a specific row without matching localized text. The simulator's system locale is

Add a `#Preview` showing a selected and an unselected row.

body (assign `selection`, then `dismiss()`). Delete the inline row hierarchy and the inline filtered
