<objective>
The single highest-leverage change in the audit: extract the duplicated History row hierarchy into
one `EventRowButton` component and make `EventRow` a plain-data view. One extraction closes six
findings, and the extraction is what makes the accessibility fixes land in one place instead of two.

- **A7-1** (`worth-fixing`): the per-event row hierarchy is written out verbatim in two files and
  has already diverged — `HistoryCalendarDayDetail` is missing the 10pt vertical padding that was
  the recorded fix for BUG 1 in `.planning/debug/resolved/history-scrollview-bugs.md`, so those
  rows are still in the pre-fix collapsed state.
- **C14-1** (`worth-fixing`): that padding is applied to the `Button`, not to its label, while
  `contentShape(Rectangle())` has already pinned the interactive shape to the inner frame — so 20pt
  of every row's height is visible but inert, and the touch target is likely under the 44pt minimum.
- **C14-2** (`worth-fixing`): `accessibilityAction` appears nowhere in the repo. Duplicate and
  Delete are reachable only through a long-press. 07-RESEARCH Assumptions Log **A1** records that
  whether `contextMenu` auto-republishes its items as VoiceOver actions could not be confirmed
  against Apple documentation — so this plan adds them explicitly and routes the answer to a
  human check rather than guessing.
- **C14-3** (`worth-fixing`): `EventRow` is a rigid three-column `HStack` with a hard-coded 36pt
  icon frame and a hard-coded 48pt divider inset, with no `@ScaledMetric`, no adaptive layout and
  no Dynamic Type cap. CLAUDE.md requires surviving AX5.
- **A6-1 / A4-1 / A4-3**: rewire the rows onto the value types 07-02 created.
- **A1-3 / C12-1 / C14-5 / C14-6**: closed as part of the same edits.

Purpose: one component, one hit target, one accessibility surface, one invalidation boundary.
Output: `EventRowButton`, a POD `EventRow`, explicit accessibility actions, and two new UI test files.
