<objective>
Close UAT gaps G-05-2 and G-05-3: the drag-to-scrub glass-chip callout on
both `AlcoholAreaChart` and `WeekdayBarChart` flickers and appears
partially clipped/embedded in the chart during a drag, on all period
scopes. `.planning/debug/insights-chart-scrub-callout-flicker-clip.md`
confirmed one shared root cause with two compounding mechanisms in both
charts' identical `RuleMark` + `.annotation(overflowResolution:)` +
chart-wide `.animation(value:)` pattern:

1. **Overflow-clamp overlap** — neither chart's y-scale reserves vertical
   headroom above the actual data max, so a `.top`-positioned annotation
   near a near-peak selection gets squeezed by `overflowResolution: y:
   .fit(to: .chart)` down into the mark's own fill instead of floating
   above it (confirmed via a stationary, non-dragging long-press at the
   chart's peak).
2. **Annotation/RuleMark desync** — a chart-wide `.animation(value:
   selectedKey/selectedLabel)` on the whole `Chart(...)` view causes the
   SwiftUI-rendered annotation to lag/stray behind the natively-rendered
   `RuleMark` during rapid `chartXSelection` updates, producing a
   stale/stray callout during a fast drag and one that visibly outlives
   the `RuleMark`'s instantaneous disappearance on release.

Both mechanisms get fixed identically on both charts (same shared root
cause, same fix, one plan — not split per chart).

Purpose: the scrub callout is the only way a user reads an exact value
off either Insights chart (CHART-01); as currently built it "doesn't look
native" and the value is sometimes unreadable, defeating the phase's own
goal.

Output: `AlcoholAreaChart.swift` and `WeekdayBarChart.swift` gain a
data-derived y-scale domain with headroom, and both charts' scrub
animation is rescoped from the whole `Chart` view to just the annotation
subtree — while keeping Reduce Motion gating both mechanisms together
exactly as before.
</objective>

## Gap Closure Context

Both gaps were diagnosed in one debug session
(`.planning/debug/insights-chart-scrub-callout-flicker-clip.md`), which
found the two mechanisms above via three on-device XCUITest diagnostics
(stationary long-press at a chart's peak, a real continuous drag, and a
post-release screenshot). The debug session explicitly flagged
`DPGlass.swift`'s low glass-chip contrast against `AreaMark`'s gradient as
a *secondary*, unconfirmed contributor to the "not fully visible"
complaint — that file is shared by `DrinkTypeTile.swift` outside Insights
and is **not** in this plan's `files_modified`; fixing the two confirmed
primary mechanisms is expected to resolve the reported symptom because
the callout will no longer render on top of the mark's saturated fill at
all once it has real clearance above it. If the human-check below still
finds the chip hard to read after this fix, that is a new, narrower gap
to raise separately, not scope creep on this plan.

This project has no automated visual-diff harness for Swift Charts
annotations (05-RESEARCH.md's Validation Architecture) — the `<automated>`
commands below are regression guards (build + existing scrub/AX test
suite stay green), not proof of the visual fix. The `<human-check>` block
in each task is the actual verification for G-05-2/G-05-3 and must be
completed on-device before this plan is considered resolved.
