<objective>
Wire native drag-to-scrub selection into both Insights charts using
`chartXSelection`, render a `RuleMark` + floating glass-chip callout on
each, and sync `AlcoholAreaChart`'s selection into `InsightsHeroCard`'s
headline so it follows the touched point and reverts to the period total
on release (CHART-01, CHART-02). Both charts' callouts honor
`accessibilityReduceMotion` (CHART-04). No `InsightsViewModel` stored
state is added — selection stays view-local `@State`/`@Binding` per
REQUIREMENTS.md's explicit Out-of-Scope boundary.

This is the phase's tracer: Task 1 wires the full path — touch → native
selection → categorical-key lookup → glass-chip callout → hero headline
sync → reduceMotion-gated motion — for `AlcoholAreaChart` end-to-end,
proven by a real drag-driven UI test. Task 2 expands the identical,
already-proven pattern onto `WeekdayBarChart` (D-04, D-05).

Purpose: today both charts are "dumb" views with no interaction —
Insights data can only be read from static marks and axis labels. This
plan makes every plotted point individually readable via touch, with the
hero card surfacing the exact value scrubbed, matching the "must feel
native iOS 26" requirement from the source todo.

Output: `ChartPoint.key(for:)` promoted to a single shared helper;
`AlcoholAreaChart` and `WeekdayBarChart` both gain scrub selection +
callout + reduceMotion gating; `InsightsHeroCard` gains the
follow/revert wiring; two new `drinkpulseUITests` methods proving the
drag-to-scrub interaction end-to-end.
</objective>

## Research Open Questions — Resolution Approach

RESEARCH.md left three questions to planning. This plan resolves two of
them directly (the third belongs to 05-02-PLAN.md):

- **Open Question 1** (`@State`/binding ownership split): resolved per
  RESEARCH.md's own recommendation — `AlcoholAreaChart` stays a "dumb"
  view owning a caller-provided `@Binding var selectedKey: String?`;
  `InsightsHeroCard` is the actual `@State` owner. `WeekdayBarChart` has
  no parent hero element, so it owns `@State private var selectedLabel:
  String?` itself, fully self-contained.
- **Open Question 2** (whether `WeekdayBarChart`'s 7-bar callout needs
  edge-clamping): resolved — apply `overflowResolution` on both charts
  regardless, per D-04's "identical treatment" requirement; the cost is
  one parameter and it guards against future data changes.
