# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note (read first):** This phase is native SwiftUI + Swift Charts —
adding `chartXSelection`-driven scrub interaction to two existing "dumb" chart
views (`AlcoholAreaChart`, `WeekdayBarChart`) plus an `AXChartDescriptorRepresentable`
conformance for VoiceOver. There is no npm/shadcn ecosystem in this project
(`drinkpulse` is a native Swift/SwiftUI app — no `components.json` or
`package.json` at the repo root), so the shadcn initialization gate does not
apply. Every visual decision this phase needs is already locked in
`05-CONTEXT.md` (D-01 through D-09) and confirmed technically feasible by
`05-RESEARCH.md`; this document restates those decisions in contract form and
resolves the remaining construction details research explicitly deferred to
planning (exact copy templates, exact spacing/color values, motion gating).

## Spacing Scale

Standard 8-point spacing scale is this project's general convention but is
not strictly enforced for compact chip/badge elements already shipped in
`Features/Insights/` (e.g. `TrendBadge`: 10pt/5pt; the `DPGlass` preview
chip: 12pt/6pt). Per `05-CONTEXT.md`'s guiding principle — reuse existing
tokens rather than inventing new visual language — the new scrub callout
continues that established chip convention rather than introducing a
stricter one.

| Token | Value | Usage |
|-------|-------|-------|
| Callout horizontal padding | 10pt | `.padding(.horizontal, 10)` on the scrub-callout `Text` — matches `TrendBadge`'s existing 10pt horizontal chip padding in the same `InsightsHeroCard.swift` file |
| Callout vertical padding | 6pt | `.padding(.vertical, 6)` — matches the `DPGlass.swift` preview chip's existing 6pt value |
| Callout corner radius | 14pt | Inherited automatically from `.dpGlassCard(.chip)` (D-02) — do not override with a custom `cornerRadius` |
| Annotation-to-RuleMark spacing | Default (no override) | `.annotation(position: .top, ...)`'s built-in spacing; no custom `spacing:` parameter is introduced |
| Chart frame height (both charts) | Unchanged — 100pt (`AlcoholAreaChart`), 160pt (`WeekdayBarChart`) | This phase does not resize either chart; selection/callout renders inside the existing frame |

Exceptions: none beyond the not-strictly-4-based chip precedent noted above,
which is an intentional continuation of existing app convention, not a new
exception.

## Typography

This phase introduces exactly one new text style — the scrub callout. All
other visible typography (hero headline, axis labels, weekday bar labels) is
reused verbatim from existing code; only the *value* bound into the hero
headline changes per CHART-02, not its styling.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Scrub callout (new, both charts) | 12pt (`.caption`) | Semibold (600) | Single line, system default `.caption` line height — no custom override; `.lineLimit(1)` + `.minimumScaleFactor(0.6)` applied (see Dynamic Type note below) |
| Hero headline (existing, unchanged style — value now follows touch per CHART-02) | 40pt (`.system(size: 40, design: .rounded)`) | Bold (700) | Single line, `.lineLimit(1)` + `.minimumScaleFactor(0.5)` (pre-existing `InsightsHeroCard.swift` behavior, untouched) |
| Axis / weekday labels (existing, unchanged) | 11pt (`.caption2`) / default axis label size | Regular (400) | Single line, unchanged |

**Dynamic Type note:** the hero headline already defends against overflow at
large Dynamic Type sizes via `minimumScaleFactor(0.5)` — the new callout must
follow the identical established pattern (`lineLimit(1)` +
`minimumScaleFactor(0.6)`, slightly less aggressive since the callout string
is shorter) rather than allowing multi-line wrap inside a floating
annotation. Verification at AX5 is captured as a backstop in UI
Considerations below (chip width vs. chart bounds is a real risk research
flagged, not something resolvable on paper alone).

## Color

Not a fresh 60/30/10 screen palette — this phase adds interaction affordances
on top of an existing, already-colored Insights screen. No new hex/asset
color is introduced; every value below is either an exact reuse or an
explicit reservation.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (existing, unchanged) | System background (`Color(.systemGroupedBackground)` / `.systemBackground`, adaptive) | Screen background — untouched by this phase |
| Secondary — callout surface (existing token, reused) | Liquid Glass effect via `.dpGlassCard(.chip)` (`glassEffect(.regular, in: .rect(cornerRadius: 14))`) | Scrub callout background on both charts (D-02, D-04) — exact reuse, no new token |
| Accent (10%, new this phase) | `Color.secondary.opacity(0.3)` | **Reserved for:** the vertical scrub-indicator line (`RuleMark` stroke) only, on both `AlcoholAreaChart` and `WeekdayBarChart` — never applied to callout text, chip background, or any other element |
| Existing chart data colors (unchanged, not this phase's decision) | `Color.dpRiskModerate` (area fill/line gradient); `RiskLevel.chartColor` → `.dpRiskLow` / `.dpRiskModerate` / `.dpRiskHigh` (bar fill, from `Assets.xcassets` adaptive colorsets) | Data-encoding colors already in place — this phase does not recolor marks on selection; the touched bar/point keeps its existing risk-level color |
| Destructive | not applicable | No destructive action exists in this phase |

Accent reserved for: the `RuleMark` scrub-indicator line only. There is no
button, no CTA, and no other interactive affordance in this phase to compete
for the 10% accent role.

## Copywriting Contract

This phase adds no button, no new empty/error state, and no destructive
action — it only adds a drag-to-reveal callout on data that already renders.
The load-bearing copy contract is the exact callout/VoiceOver phrasing
below, which must share one formatting source (`vm.formattedValue(_:)`) to
satisfy D-01/D-08's "never drift apart" requirement.

| Element | Copy |
|---------|------|
| Primary CTA | not applicable — no button or new call-to-action is introduced; the interaction is a drag gesture on an existing chart |
| Empty state heading | not applicable — no new empty state; the existing `AlcoholAreaChart` empty-state text (`insights.areaChart.empty`, shown when all points are 0g) is untouched, and scrubbing cannot be triggered while that branch renders (the `Chart` view with `chartXSelection` isn't in the view tree in that state) |
| Empty state body | not applicable (see above) |
| Error state | not applicable — no network/parsing/error path is introduced; scrubbing only reads already-validated in-memory `ChartPoint`/`WeekdayBar` values |
| Destructive confirmation | not applicable — no destructive action in this phase |
| **Scrub callout — `AlcoholAreaChart` (new, D-01)** | Template: `"{abbreviated month} {day} — {formattedValue}"` → e.g. `"Jul 24 — 32 g"`. Date via `.dateTime.month(.abbreviated).day()`; value is `vm.formattedValue(point.grams)` verbatim, never reformatted inline |
| **Scrub callout — `WeekdayBarChart` (new, D-05)** | Template: `"{bar.label} — {formattedValue}"` → e.g. `"Mon — 18 g"`. `bar.label` reused as-is (already localized, e.g. "Mon"); value formatted through the chart's existing `unitDivisor`/`unitLabel` display path — no risk-level text appended (D-05) |
| **VoiceOver per-point announcement — `AlcoholAreaChart` (new, D-08)** | Template: `"{full month} {day}, {formattedValue}"` → e.g. `"July 24, 32 g"`. Full month via `.dateTime.month(.wide).day()`; same `formattedValue(_:)` substring as the visual callout — this is the single-source-of-truth guarantee, not a second formatting path |
| **VoiceOver per-point announcement — `WeekdayBarChart` (new, D-09)** | Template: `"{bar.label}, {formattedValue}"` → e.g. `"Mon, 18 g"`. Reuses `bar.label` as-is — no new full-weekday-name lookup is introduced (out of scope; the `WeekdayBar` model only stores the abbreviated label) |

**Punctuation contract:** the visual callout uses an em dash (`" — "`); the
VoiceOver announcement uses a comma (`", "`) for natural spoken phrasing.
Only this connective punctuation differs between the visual chip and the
spoken sentence — the date/label token and the `formattedValue(_:)` output
must be byte-identical substrings in both, per D-01/D-08.

## Interaction & Motion Contract

CHART-04's Reduce Motion requirement has two independent mechanisms that
must both be gated (Pitfall 4 in `05-RESEARCH.md`) — gating only one is a
failing implementation, not a partial pass.

| State | Behavior |
|-------|----------|
| Motion allowed (`accessibilityReduceMotion == false`) | Callout appears/disappears via `.transition(.opacity.combined(with: .scale(scale: 0.9, anchor: .bottom)))`, gated by `.animation(.spring(response: 0.3, dampingFraction: 0.8), value: selection)` — reuses `OnboardingView.swift`'s exact established spring parameters, not a new curve |
| Reduce Motion on (`accessibilityReduceMotion == true`) | Callout appears/disappears via `.transition(.identity)` and **no** `.animation(...)` modifier is applied to the selection-state change — both the transition AND the animation must be swapped; leaving either one active fails CHART-04 |
| Selection lifecycle | Selection is `nil` by default; while dragging it holds the touched key; on release it returns to `nil` (hero headline reverts, CHART-02). Per D-06, changing `vm.period` via `InsightsScopeNavigator` also forces the selection back to `nil` immediately — no carried-over selection across period switches |
| Backgrounding / tab switch mid-scrub | No explicit reset code required (D-07) — selection is view-local `@State`, naturally dropped on view rebuild |
| Hero headline (CHART-02) | While `selection != nil`: renders `vm.formattedValue(selectedPoint.grams)`. While `selection == nil`: renders `vm.formattedValue(vm.periodTotalGrams)` (existing, unchanged copy). Identical `.font(.system(size: 40, weight: .bold, design: .rounded))` styling in both states — no new type treatment for the "scrubbing" state |
| Gesture | Native `.chartXSelection(value: Binding<String?>)` only — no hand-rolled `DragGesture`/`chartOverlay` hit-testing (explicit anti-pattern in `05-RESEARCH.md`) |
| Edge clamping | `.annotation(position: .top, overflowResolution: .init(x: .fit(to: .chart), y: .fit(to: .chart)))` on both axes (D-03) — omitting either axis is a documented pitfall (callout clips/pops outside the chart near an edge) |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). "Loading" and
> "error" categories were filtered out by the relevance filter: this phase
> introduces no async fetch and no network/parsing path — Insights data is
> already loaded via `@Query` before either chart renders, and scrubbing only
> reads already-validated in-memory values. The rows below are the
> categories that do apply to this phase's `list-collection`
> (`AlcoholAreaChart`/`WeekdayBarChart` data points) and `static-content`
> (scrub callout) elements.

Applicable state considerations resolved: 3 covered, 2 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | `AlcoholAreaChart` data (list-collection, all points = 0g) | ✅ covered | Scrubbing is structurally impossible while the existing `emptyState` branch renders (`insights.areaChart.empty` text) — the `Chart`/`chartXSelection` view isn't in the tree in that state, so no callout can appear over empty-state text. Existing behavior, untouched by this phase. |
| populated | Both charts' drag interaction (list-collection, happy path) | ✅ covered | D-01 through D-05 fully specify the happy-path callout content/style for both charts; see Copywriting Contract and Interaction & Motion Contract above. |
| partial | `AlcoholAreaChart` touched point with `grams == 0` inside an otherwise-populated series (list-collection) | ✅ covered | A zero-value touched point renders through `vm.formattedValue(0)` identically to any other value — no blank or special-cased callout; e.g. `"Jul 22 — 0 g"` renders normally. |
| overflow | Scrub callout text at largest Dynamic Type (AX5) (static-content) | 🧪 backstop | Statement: "The scrub callout chip does not clip or extend past the chart's edges at the AX5 Dynamic Type size, on-device, for both charts." `overflowResolution` clamps the annotation's *position*, not its *width* — text wider than the chart at AX5 is a real risk research flagged (CLAUDE.md's Dynamic Type up to AX5 requirement); `lineLimit(1)` + `minimumScaleFactor(0.6)` is the prescribed mitigation, but must be visually confirmed on-device, not assumed from this spec alone. |
| zero-one-many | `AlcoholAreaChart` with exactly one plotted point (e.g. `.allTime` view on the very first day of app usage) (list-collection) | ⚠ unresolved | `chartXSelection`'s behavior against a single-band categorical/nominal scale is not confirmed by `05-RESEARCH.md` (adjacent to Assumption A2 — nearest-band snapping is assumed correct but not verified at N=1). Planner should treat this as an explicit assumption and add a manual single-data-point check; do not assume the callout renders correctly with only one band without verifying. |
| long-text | Scrub callout combined with the longest realistic unit label (e.g. UK "units"/US "standard drinks" phrasing via `profile.alcoholUnit`) at AX5 (static-content) | 🧪 backstop | Statement: "The scrub callout's width grows to fit the longest realistic date+value+unit-label combination at AX5 without truncating to an unreadable fragment, on-device." Overlaps with the overflow row above but specifically stresses the unit-label length variance (grams strings are short; "standard drinks"-style labels are longer) — same `lineLimit(1)`/`minimumScaleFactor(0.6)` mitigation, same on-device verification requirement. |
