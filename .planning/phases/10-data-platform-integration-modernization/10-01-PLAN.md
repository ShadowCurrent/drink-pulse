<interfaces>
StoreBootstrap today: `@MainActor static func makeContainer(schema: Schema, configuration: ModelConfiguration) throws -> ModelContainer` runs open under MigrationPlan, and on any throw calls `recoverStore(at:)` then opens again.
MigrationPlan: `schemas = [SchemaV1, SchemaV2, SchemaV3, SchemaV4]`, `stages = [v1ToV2, v2ToV3, v3ToV4]`. v1ToV2 sets event uuid = UUID(), event modifiedDate = event.timestamp, template uuid = UUID(), template modifiedDate = .now, profile modifiedDate = .now. v2ToV3 sets creationDate = consumptionDate. v3ToV4 is lightweight (adds healthKitUUID, nil).
Frozen snapshots seed with `Schema(versionedSchema: SchemaVn.self)` and a plain ModelContainer. SchemaV1 types have designated initializers; SchemaV2 and SchemaV3 types expose only init() so properties are assigned after construction.
Live types: ConsumptionEvent, DrinkTemplate, UserProfile (stored properties listed in 10-RESEARCH.md Migration Determinism).
RecordDeduplicator.sweep(in:) is @MainActor and groups strictly by uuid; it also runs UserProfileStore.deduplicated, so seed exactly one profile per store.
</interfaces>
