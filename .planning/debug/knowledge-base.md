## history-scrollview-bugs — History list rows cramped + scroll-to-bottom pagination stuck after List->ScrollView migration
- **Date:** 2026-08-03
- **Error patterns:** rows shorter/cramped than before, ScrollView LazyVStack, missing vertical padding, scroll to bottom does not load older entries, pagination stuck, onAppear not firing, extendListWindow, LoadMoreSentinel, contextMenu content build start firing during scroll
- **Root cause(s):** BUG 1: HistoryDaySectionCard's per-row Button{EventRow} content was missing `.padding(.vertical, 10)` (dropped during the plan-0038 List->ScrollView extraction; SettingsRow/plan-0027 applies this to every row and was the pattern being mirrored); BUG 2 (AND-gated, two contributing causes): (a) LoadMoreSentinel used `.onAppear`, which is documented as unreliable inside ScrollView+LazyVStack because LazyVStack computes content geometry from an estimate for not-yet-measured trailing subviews, so a genuine scroll-to-bottom can stop at the wrong estimated offset without the sentinel ever registering appeared; (b) extendListWindow only advanced the fetch window by one listPageDays page per trigger, so once the trigger became reliable, a data gap spanning more than one page required several sequential firings to converge.
- **Fix:** BUG 1: added `.padding(.vertical, 10)` to the row Button content in HistoryDaySectionCard.swift, matching SettingsRow's convention. BUG 2: replaced LoadMoreSentinel's `.onAppear` with `.onScrollVisibilityChange(threshold: 0)` (iOS 18+) plus a defensive one-shot latch, and added `HistoryViewModel.extendedWindowStart(from:earliest:calendar:)` to collapse consecutive empty pages into a single window jump.
- **Files changed:** drinkpulse/Features/History/Components/HistoryDaySectionCard.swift, drinkpulse/Features/History/HistoryListQueryView.swift, drinkpulse/Features/History/HistoryView.swift, drinkpulse/Features/History/HistoryViewModel.swift, drinkpulse/UITestSeed.swift, drinkpulse/UITestSeed+Fixtures.swift, drinkpulseTests/Features/History/HistoryViewModelTests.swift, drinkpulseTests/Features/History/HistoryViewModelTests+Pagination.swift, drinkpulseUITests/Features/History/HistoryInteractionUITests+Pagination.swift
- **Why not caught:** No gate existed for either bug class at the time of the plan-0038 List->ScrollView migration. Row padding is a visual/layout regression invisible to build/typecheck/unit tests (no snapshot or layout-assertion test covered row height), and no UI test previously exercised the "scroll to bottom triggers pagination" end-to-end flow — the migration shipped without a UI test for its own primary interaction (build clean + existing unit tests green gave false confidence).
- **Recurrence guard:** Two new regression tests now cover this class: `drinkpulseUITests/Features/History/HistoryInteractionUITests+Pagination.swift:test_scrollToBottom_loadsOlderEntries` (end-to-end scroll-to-bottom pagination, paginationstress fixture) and `drinkpulseTests/Features/History/HistoryViewModelTests+Pagination.swift` (4 tests covering `extendedWindowStart(from:earliest:calendar:)` gap-collapse logic). This knowledge-base entry itself is the recurrence guard for row-padding-dropped-during-extraction: future List->X extractions should diff against the SettingsRow/plan-0027 padding convention explicitly.
