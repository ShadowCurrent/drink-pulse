<objective>
Move `sharedModelContainer` creation off the synchronous `App.init` path and
replace both `fatalError` container-failure crashes with a real, designed,
retryable error screen. `drinkpulseApp` gains a 3-case `ContainerLoadState`
(`.loading` / `.ready(ModelContainer)` / `.failed(StartupError)`) populated
from a `.task` that runs after the first frame renders; `.failed` shows a new
full-screen `StartupErrorView` (Retry + Share Diagnostic Details), never a
crash.

Purpose: today `sharedModelContainer` is an eagerly-evaluated stored property
that runs `ModelContainer(for:...)` synchronously as part of `App.init`,
`fatalError`-ing the whole app if it throws — a store-open failure (low disk,
migration issue, corruption) currently crashes on launch with no recovery
path. This plan makes the store open after the first frame and gives failure
a real, retryable UI instead of a crash.

Output: `ContainerLoadState.swift`, `StartupError.swift`, `StartupErrorView.swift`
(new); `drinkpulseApp.swift` restructured; `UITestSeed.swift` gains a
deterministic forced-failure hook; new unit + UI test coverage; `docs/architecture.md`
and `docs/DEVLOG.md` updated to describe the new startup sequence.
</objective>
